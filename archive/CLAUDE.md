# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

DesignNote is a Chrome (Manifest V3) extension that lets a user mark up any webpage with Figma-style annotation comments, keyed to the page URL and saved locally via `chrome.storage.local`. No build step, no bundler, no package.json — it's plain vanilla JS/HTML/CSS loaded directly by Chrome.

## Running / testing changes

There is no build step. Dependency-free checks (Node only):

- `node tests/selector-fingerprint.test.js` — selector fingerprint fallback (correctness + no exponential blow-up)
- `node tests/content-helpers.test.js` — CSV quoting/formula guard, XML escaping, category normalisation
- `node tests/mcp-structure.test.js` — the MCP bridge's site → section → page → category grouping, inferred kinds, filters
- `node tests/browser-selector.js` — selector fixes in a real page (shifted paths, generated ids/classes, ambiguous text, anchor text)
- `node tests/browser-bridge.js` — AI agent bridge end to end: real extension + real `mcp/redlines-mcp.js` over stdio (origin/pairing-code refusal, shared sites, screenshots toggle, read-only default, sidebar tags/replies, Re-pin, live refresh, popup agents strip: count, blink while working, hover card; `SHOT_DIR=<dir>` saves a popup screenshot)
- `node tests/browser-annotation-ui.js` — annotation UI v2 in real Chrome: one-line composer (Save readiness, connector, writing state, category chip add/rename), sidebar filters and actions (resolve, send, delete + undo, screenshot viewer, tooltips), table actions, Settings surfaces
- `node tests/browser-smoke.js [extDir]` — loads the real extension into desktop Chrome via `--remote-debugging-pipe` + `Extensions.loadUnpacked` and drives the in-page UI on local fixtures (`HEADED=1` to watch). Plain `--load-extension` is ignored by current branded Chrome.

Test plan and results: `docs/testing/`. To try changes by hand:

1. Open `chrome://extensions`, enable **Developer mode**, click **Load unpacked**, select this folder.
2. After editing any file, go back to `chrome://extensions` and click the reload icon on the DesignNote card (content script changes also require reloading the target page).
3. For local `file://` pages, enable "Allow access to file URLs" on the extension's details page.

## Architecture

Five independent JS files, no shared module system (no imports/exports) — files communicate via `window.__designNoteGetSelector`, `chrome.runtime` messages, and `chrome.storage.local`.

- **`selector.js`** — content script loaded first. Exposes `window.__designNoteGetSelector(el)`, a best-effort unique CSS selector generator (non-generated id → stable/aria attrs → semantic class → nth-child path fallback, max depth 8), `__designNoteGetSelectorWithFingerprint(el)` → `{ selector, fingerprint, anchor }`, and `__designNoteFindElement(selector, fingerprint)`. An nth-child path hit is only trusted if it still matches the fingerprint's tag + text; a fingerprint match needs two agreeing clues or one unique one. Method `'none'` means lost: show "Element not found" + Re-pin, never guess. `content.js`'s `findAnnotationEl` must go through `__designNoteFindElement`.
- **`prefs.js`** — loaded after `selector.js` and before `content.js`/`theme.js` (manifest, `sendToTab` injection list and every extension page). Exposes `window.__dnPrefs`: applies the Appearance settings in `dn_appearance` (accent colour, corners, text size, UI font, glass, motion, page pins, note colours) as `data-dn-*` attributes plus inline `--dn-accent-*` tokens derived from the chosen colour (readable text variants for each theme). Default values set nothing, so `design-tokens.css` stays the source of truth.
- **`content.js`** — the main content script (IIFE), injected into every page. Owns all in-page UI: the "Mark"/"Notes" toggle buttons, the slide-out sidebar, the click-to-annotate popup form, and screenshot cropping. All DOM it creates lives under a single `#designnote-root` element to isolate it from host page styles/scripts. Annotations are stored per-URL under key `dn_annotations::<url-without-hash>` in `chrome.storage.local`; each annotation is `{ id, type, text, selector, fingerprint, anchor?, pageTitle?, rect, screenshot, timestamp, updatedAt?, copiedAt?, status?, resolvedAt?, resolvedBy?, replies?, source?, assignee? }` (`assignee` = `{ id, name }` of the AI tool the note was sent to; see data model in docs/GUIDE.md; missing `status` = open). Change single notes with `updateAnnotation()` (re-reads storage first); a `storage.onChanged` listener refreshes the open sidebar when an AI agent or another tab changes this page's notes. `type` is one of the 4 presets (`text|suggestion|bug|note`, lowercase) **or** any custom category string — never assume only the 4 values. Exporters take an explicit `scope` ('current' | 'all'); the sidebar always passes 'current'.
- **`background.js`** — the MV3 service worker. Handles two message types from content scripts: `CAPTURE_SCREENSHOT` (via `chrome.tabs.captureVisibleTab`) and `ENHANCE_PROMPT` (calls out to whichever AI provider is configured — Anthropic, OpenAI, or OpenRouter — using the API key from `chrome.storage.local`, and rewrites a raw annotation into a structured coding-agent prompt).
- **AI agent bridge** — `mcp/redlines-mcp.js` is a dependency-free Node MCP server (stdio) that the user's AI tool starts with `REDLINES_TOKEN`. It listens on `127.0.0.1:17337` (`REDLINES_PORT`) and accepts only `chrome-extension://`/`moz-extension://` origins. `background.js` (`connectBridge`, off unless `dn_bridge_enabled`) connects out to it, sends the pairing token, and answers `list | get | current | show | write`. **All data rules live in `bridgeCall` in `background.js`, never in the server:** shared sites (`dn_bridge_sites`), screenshots (`dn_bridge_screenshots`), writes (`dn_bridge_write`, off by default), text caps, and the `dn_bridge_log` activity log. The server only formats (grouping, inferred kinds). Status is in `chrome.storage.session.dn_bridge_status`. Settings → "Connect to AI agents" turns it on (trusted click + consent) and shows the setup per AI tool (agent picker with logos).
  - **Several agents at once:** each AI tool starts its own server, which takes the next free port from the base (range of 10); `background.js` connects to every port in the range (`bridges` map). The server names its tool from MCP `initialize` `clientInfo` (`agentFrom`, ids = `icons/agents/<id>.svg`, Simple Icons CC0) and sends `{type:'agent'}`; live agents are in `chrome.storage.session.dn_bridge_agents` (one entry per kind, from `liveAgents()`: `{ id, name, sessions, since, calls, busy, lastAt, seen, assigned }` — `busy` = requests in flight, `seen`/`assigned` = notes visible / open notes sent to it as of its last request; published on every call's start and end). `dn_bridge_log` entries carry `agent` (the asking agent's id). The note form's "Send to" row asks `GET_AGENTS` (empty on sites not shared with agents) and saves `assignee`; the agent reads its notes with `get_my_annotations`.
- **`popup.js`/`popup.html`** — the toolbar popup (annotation count + shortcuts to open sidebar / settings) and the **AI agents** strip: connected agents and their count, a chip that blinks while that agent has a request in flight (and for 2.5 s after), and a details card on hover / keyboard focus (online for, requests, notes it can see, open notes sent to it, its last 3 requests from `dn_bridge_log`). Chips are keyed by agent id and updated in place by a 1 s tick, so focus and an open card survive re-renders.
- **`settings.js`/`settings.html`** — the options page for choosing an AI provider and entering its API key (`dn_provider`, `dn_api_key` in `chrome.storage.local`).

### Message flow

- `content.js` / `settings.js` → `chrome.runtime.sendMessage` → `background.js`: `CAPTURE_SCREENSHOT`, `ENHANCE_PROMPT`, `UPLOAD_TO_DRIVE`, `CHECK_DRIVE`, `DISCONNECT_DRIVE`, `GET_AGENTS` (all async, `return true`).
- `popup.js` → `background.js` `TAB_MESSAGE {tabId, message}` → `sendToTab()` → `content.js`. Keyboard commands go through `runCommand()` → `sendToTab()` too. `sendToTab` injects `selector.js`/`content.js` + CSS via `chrome.scripting` when the tab has no live content script (opened before install, or orphaned by an extension reload/update). Never send tab messages around it.
- `content.js` handles `TOGGLE_SIDEBAR_OPEN` (open), `TOGGLE_SIDEBAR` (shortcut toggle), `SHOW_PILL`, `TOGGLE_PILL`, `TOGGLE_MARK_MODE`, `GET_ANNOTATION_COUNT`, `JUMP_TO_ANNOTATION {id}` (the bridge's `show_annotation`, sent via `sendToTab`).
- An orphaned content script (after an extension update) can't call `chrome.*`. `content.js` guards UI clicks with `extensionAlive()`, and a fresh injection removes the stale `#designnote-root`.
- While a modal `<dialog>` is open, `placeRoot()` moves `#designnote-root` inside it (everything else is inert). `#designnote-root` is a fixed, zero-size stacking context at z-index 2147483647.
- **Outbound actions** (Enhance, Send to Google Drive) must: act only on `event.isTrusted` input, go through `confirmOnce()` (one-time consent text that names what is sent), and send only from `background.js`. `enhancePrompt` strips the page URL to origin + path (`pageAddressForAi`). Settings' silent Drive check must stay network-free (cached `dn_drive_account`). Never write to the host page's `localStorage`. `escapeHtml` must stay attribute-safe (escapes quotes). `node tests/browser-privacy.js` guards all of this offline (fetch/identity mocked, external hosts blocked).
- `node tests/browser-env.js` covers these paths (popup, shortcuts handler, reload, SW restart, SPA, theme, viewport, host CSS, dialogs).
- **Annotation UI v2 conventions** (spec: DESIGN.md → *Annotation UI v2*): the form is a one-line composer (`openForm`); its Save is `aria-disabled`, never `disabled` (stays focusable; the click reads the live text). The connector `#dn-form-link` is an SVG, so toggle it with the `hidden` *attribute*. Note actions are `.dn-act[data-act]` built once by `actionsHtml()` and handled by `noteAction()` for both sidebar cards and table rows; sending a note to an AI agent is `sendToAgent()` (the orange button on each note); the create form also has icon-only agent toggles (`#dn-form-agents`, from `GET_AGENTS`, saved as `assignee`). The form's category menu (`#dn-type-picker`) is always closed on open and only the arrow `#dn-cat-toggle` opens it. Tooltips are `data-tip` sentences (one `.dn-tip` element), not `title`. Action hues are `--dn-act-*` tokens.
- **Keyboard and accessibility:** Escape is handled once on `#designnote-root`: it closes the innermost layer (menu → table → sidebar), and only while focus is inside our UI. The forms and Mark mode handle their own Escape. Every close path returns focus to the control that opened it. Text colours come from `design-tokens.css`: `getTypeColor()` returns `var(--dn-type-*-text)` or `hsl(… var(--dn-type-custom-l))`, never fixed hex values. Contrast is checked over both light and dark host pages. `node tests/browser-a11y.js` guards this; findings are in `docs/ux/UX_AUDIT.md`.

### Key constraints to preserve

- Content script UI must stay scoped under `#designnote-root` (see `content.css`'s `all: revert` reset) so it doesn't inherit or leak styles into the host page.
- Everything except the "Enhance" feature must keep working fully offline — don't introduce network calls into `content.js` or the annotation save/load path. The only other connection is the opt-in bridge's WebSocket from `background.js` to `127.0.0.1`.
- API keys are only ever sent directly from `background.js` to the selected provider's API, never anywhere else.
- `selector.js` must load before `content.js` (order matters in `manifest.json`'s `content_scripts.js` array) since `content.js` calls `window.__designNoteGetSelector`.

Known limitations worth knowing before "fixing" them (see docs/GUIDE.md for full details): selector fragility on heavily client-rendered pages, screenshots only capture the visible viewport, no cross-device sync (local-first by design).
